# CausaFlux v1.7.0

Version **1.7.0** is the **Foundation Adapter and Pretraining** release. It adds external contracts for scGPT, GET, Nicheformer, MrVI, ESM-2, MolFormer and DINOv2 plus a CausaFlux multi-objective foundation encoder evaluated on dynamic and intervention transfer.

> **Research-use status:** the bundled foundation benchmark is synthetic software validation. External foundation checkpoints are not redistributed, and real foundation-pretraining authorization remains blocked until the real longitudinal, multimodal, intervention and spatiotemporal gates are satisfied.

## Quick start

```bash
cd ~/Downloads/CausaFlux_v1.7.0
sh run.sh
```

The default command runs the foundation pretraining benchmark.

```bash
causaflux foundation-pretrain-run --output causaflux_v1.7.0_foundation_pretraining --require-gate
causaflux foundation-pretrain-validate --input causaflux_v1.7.0_foundation_pretraining
causaflux foundation-adapter-list
causaflux foundation-objective-list
```

### v1.7 exit criterion

Pretraining must improve **future-state** and **intervention-effect** transfer relative to the same-capacity non-pretrained encoder. Required evaluations include frozen/linear probes, PEFT, full fine-tuning, zero-shot transfer, donor holdout, tissue holdout, perturbation holdout and a prospective-time proxy. Cell-type annotation is reported but cannot satisfy the gate.

See `docs/FOUNDATION_ADAPTER_PRETRAINING.md`.

### Evidence boundary

The bundled CPA/GEARS/TxPert/scGPT `AdapterProxy` rows are lightweight interface-regression baselines, **not executions of the published models**. The real established-method gate remains blocked until row-aligned predictions generated by actual external model environments are imported. The synthetic software gate therefore validates implementation and generalization logic, not scientific superiority to those external methods.

## Retained v1.4 multimodal release documentation



**CausaFlux** is a Python research platform for dynamic, intervention-aware modeling of cellular and tissue-state evolution.

Version **1.4.0** is the **Multimodal Dynamic State Model** release. It adds modality-specific encoders, product-of-experts and mixture-of-experts fusion, modality-dropout training, cross-modal decoders, explicit missing-not-at-random sensitivity analysis, early-imaging-to-late-omics forecasting, phosphoproteomic/metabolomic/lipidomic modalities, and donor/cohort-aware latent context.

> **Research-use status:** The bundled v1.4 multimodal benchmark is a deterministic synthetic software fixture. It validates architecture, missingness handling, cross-modal decoding, calibration, and exit-gate logic. It is not biological evidence or clinical guidance.

## One-command macOS run

```bash
cd ~/Downloads/CausaFlux_v1.4.0
```

The default command runs the v1.4 multimodal dynamic benchmark and opens its report. Python 3.13 is detected and redirected to a project-local Python 3.10–3.12 environment.

## v1.4 model comparison

Prespecified baselines:

Dynamic models:

- `EarlyImagingReporterGRU`
- `CausaFluxPoEDynamic`
- `CausaFluxMoEDynamic`
- `CausaFluxPoE_NoImagingReporter` ablation

The PoE/MoE models include modality-specific encoders, learned temporal state, donor/cohort context, and late-omics decoders.

## Multimodal exit criterion

At least one dynamic model using the **history of early imaging and pathway reporters** must have:

- lower validation-calibrated test log loss than all three prespecified baselines;
- lower Brier score than all three baselines;
- AUC non-inferior to the strongest baseline within 0.02;
- zero train/test perturbation-history overlap.

The reference software gate passes, but foundation pretraining remains **blocked** until the same gate passes on a locked real longitudinal multimodal perturbation dataset.

## Retained ten-stage disease-evolution workflow

```text
1. Multimodal baselines, donor-aware calibration, and bootstrap uncertainty
2. Tumor–immune–stromal spatial graph, niches, circuits, and transitions
3. Donor-aware causal treatment effects
4. Gene, drug, combination, sequence, and timing counterfactual therapeutics
5. Early-warning and causal-proximity biomarkers
6. Closed-loop CRISPR, drug, imaging, and sampling-time design
7. Neural–glial trajectories, imaging, electrophysiology, and APOE context
8. Integrated cancer and neurobiology reports and model card
9. Publication graphics, vector/raster bundles, panel source data, and visual regression
10. Platform provenance, dataset cards, artifact hashes, and validation gates
```

Each stage reads and writes explicit artifacts. This keeps the workflow auditable and avoids maintaining incompatible native scientific runtimes in one long-lived process.

## Scientific limitations

CausaFlux formalizes assumptions and quantifies uncertainty; it cannot make observational data causal by itself. Real studies require explicit causal identification, appropriate controls, measured interventions, biological replication, independent cohorts, assay validation, and expert interpretation. High performance on the synthetic reference cohorts is deliberately learnable and should not be used as an estimate of real-world accuracy.
